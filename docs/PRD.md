## 一、产品概述

### 1.1 产品名称
**Cor-AiWorker**

### 1.2 产品定位
基于多 Agent 协作的团队开发对齐系统。参考 Lobechat 等 AI 协作平台的交互理念，为开发团队提供一套以 AI Agent 为核心的任务协作、进度对齐与智能辅助平台。

### 1.3 核心价值
- **多 Agent 协作**：支持多个 AI Agent 并行工作，各司其职，协同完成复杂任务
- **团队对齐**：实时同步团队成员与 Agent 的工作状态，消除信息差
- **开发提效**：将重复性、规律性的开发任务交由 Agent 处理，人类专注于创造性工作
- **可观测性**：完整的 Agent 执行日志与任务追踪，确保过程透明可控

### 1.4 目标用户
- 中小型软件开发团队
- 希望引入 AI 辅助开发流程的技术负责人
- 需要多人协作、任务对齐的项目管理者

## 四、功能详细说明

### 4.1 用户功能

#### 4.1.1 CorWork 需求对齐
> 核心功能，对标当前 AI 辅助协作工作流

- **AI 辅助协作**：所有协作流程均有 AI 参与，提供智能建议与自动化执行
- **群聊模式**：支持多人 + 多 Agent 同处一个协作空间，实时沟通与任务对齐
- **需求对齐流程**：从需求输入 → AI 拆解 → 任务分配 → 进度跟踪，全流程闭环

#### 4.1.2 Skill / MCP 功能上传
> 能力扩展市场，支持用户自建与共享

- **Skill 上传**：用户可将自定义技能（Skill）上传至平台，供自己或团队使用
- **MCP 接入**：支持 MCP（Model Context Protocol）协议，接入外部工具与服务
- **自建能力**：用户可自行开发并注册新的 Skill / MCP，扩展 Agent 能力边界
- **能力共享**：已上传的 Skill / MCP 可在团队内共享复用

#### 4.1.3 WorkBench 工作台
> 团队协作的核心看板与管理中心

- **协作进度**：实时查看当前所有任务与 Agent 的执行状态
- **API 用量监控**：展示各模型 API 的调用量、费用消耗与剩余额度
- **日程管理**：团队日程与任务 deadline 的统一视图
- **定时任务**：支持配置定时触发的 Agent 任务（如每日站会摘要、定时报告生成）

#### 4.1.4 ChatAgent
> 智能对话入口，支持记忆与路由

- **用户记忆（本地存储）**：Agent 记住用户的偏好、习惯与历史上下文，提供个性化响应；记忆数据本地存储，保护隐私
- **对话记录**：完整保存历史对话，支持检索与回顾
- **对话路由**：用户可通过自然语言对话直接触达各功能模块（如"帮我看看今天的任务进度"→ 路由至 WorkBench）

---

### 4.2 开发者功能

#### 4.2.1 日志查看
- **Agent 执行日志**：查看每个 Agent 的详细执行过程、输入输出与耗时
- **系统日志**：后端服务运行日志，便于排查问题
- **日志过滤与搜索**：按时间、Agent、任务、日志级别等维度筛选

#### 4.2.2 API 管理
- **API Key 管理**：统一管理各模型服务的 API Key，支持新增、编辑、删除
- **接口调试**：内置 API 调试工具，方便开发者测试接口
- **用量统计**：各 API Key 的调用量与费用明细

---

### 4.3 实验功能

> 实验性功能，优先级较低，探索阶段，可能随时调整。

#### 4.3.1 协作人工介入 + MCP 积木搭建 + 工作流可视化
- **人工介入节点**：在 Agent 自动化流程中插入人工审核节点，确保关键决策由人把控
- **MCP 积木搭建**：以可视化拖拽方式组合 MCP 工具，搭建自定义工作流
- **工作流可视化**：以流程图形式展示 Agent 协作的执行路径与当前节点状态

#### 4.3.2 养成龙虾（等级 / 梦境系统）
- **等级系统**：用户与 Agent 通过完成任务积累经验值，解锁更高等级与能力
- **梦境系统**：探索性玩法，具体形态待定
- **游戏化激励**：通过养成机制提升用户粘性与使用积极性

## 五、用户故事（User Stories）

### US-001：需求对齐协作
> 作为开发团队成员，我希望在 CorWork 中与 AI 和队友共同对齐需求，让 AI 自动拆解任务并分配，减少会议时间。

### US-002：自建并上传 Skill
> 作为开发者，我希望将自己写的代码审查脚本封装成 Skill 上传到平台，让团队所有人都能通过 Agent 调用它。

### US-003：通过 WorkBench 掌握全局
> 作为项目经理，我希望在 WorkBench 上一眼看到今天所有任务进度、API 消耗情况和即将到期的 deadline，不需要切换多个工具。

### US-004：ChatAgent 路由到功能
> 作为普通用户，我希望直接用自然语言告诉 ChatAgent "帮我安排明天的开发任务"，它能自动理解并跳转到对应功能完成操作。

### US-005：开发者排查问题
> 作为后端开发者，我希望在日志查看页面快速定位某个 Agent 执行失败的原因，并看到完整的调用链路。

### US-006：搭建自定义工作流（实验）
> 作为高级用户，我希望通过拖拽 MCP 积木搭建一个"每天早上自动拉取 Jira 任务 → 生成日报 → 发送到群聊"的工作流。

## 六、非功能性需求

| 类别 | 要求 |
|------|------|
| 性能 | 页面首屏加载 < 3s，Agent 响应延迟 < 5s（不含模型推理时间） |
| 可用性 | 系统可用性 ≥ 99%（开发阶段不作强制要求） |
| 安全性 | API Key 加密存储，用户数据隔离，HTTPS 传输，本地记忆数据不上传 |
| 可扩展性 | 支持横向扩展，Agent 数量不受硬性限制，Skill/MCP 插件化架构 |
| 兼容性 | Web 端支持 Chrome / Edge / Safari 最新版本 |
